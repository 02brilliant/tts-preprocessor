# 2단계 Diff 표시 설계

## 단계와 출력

| 단계 | 출력 필드 | 화면 Diff |
| --- | --- | --- |
| 1단계 규칙 기반 처리 | `normalized_text` | 원본 → 1단계 |
| 2단계 통합 LLM 처리 | `speech_text` | 1단계 → 2단계, 원본 → 2단계 누적 |

통합 LLM 단계는 읽기·발음·운율을 한 번에 처리한다.

## 변경 출처

- 원본과 같은 문자는 무색으로 유지한다.
- 1단계에서 삽입·교체된 표면은 초록색으로 표시한다.
- 2단계에서 삽입·교체된 표면은 파란색으로 표시한다.
- 출력에서 삭제된 원본 표면은 빨간색 취소선으로 표시한다.
- 삽입된 공백은 `␣` 기호로 시각화하고, 삽입된 쉼표는 점선 테두리로 표시한다.

누적 Diff는 단계별 LCS 결과에 원본 인덱스와 마지막 변경 단계를 전달하는 ledger를
사용한다. 따라서 2단계가 1단계 결과를 그대로 보존한 표면은 1단계 색상을
유지한다.

## LLM 처리 저하

통합 LLM 출력은 발음 철자를 바꾸고 쉼표·ASCII 공백을 추가할 수 있지만 입력에
있던 공백, 줄바꿈, 고정 문장부호를 삭제하거나 바꿀 수 없다.

계약 위반, 공급자 timeout·연결 실패·잘못된 응답, 프로세스 제한시간 초과,
회로 개방과 동시 실행 한도 초과는 모두 안전한 단계별 확정 결과로 복구한다.
2단계 결과 상자와 복사 버튼에는 API의 검증된 `speech_text`만 사용한다.
모델 원출력, 태그, `rejected_speech_text`는 화면·복사 텍스트·오류 본문에
노출하지 않는다.

화면은 `fallback_used`가 참이면 처리 저하 상태를 표시하고,
`validation_failure`가 있으면 원문 없이 코드와 심각도만 진단에 사용한다.
Diff는 규칙 및 검증된 코드 조합 결과만 대상으로 하며 HTML 이스케이프 후
렌더링한다.
