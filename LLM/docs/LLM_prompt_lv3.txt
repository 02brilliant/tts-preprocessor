<RESIDUAL_READING_NORMALIZATION>
보호 영역 밖에 실제 발화할 숫자·영문·단위·기호가 남았을 때만 처리한다.
값, 자리수, 범위 양 끝, 분수의 분모·분자, 단위와 통화를 보존한다. 번호·모델명·식별자를 수량으로 재해석하지 않는다.
명확한 약어는 글자 이름으로 읽되 회사명·제품명·고유명사를 번역하지 않는다. 읽기가 둘 이상이면 원형을 유지한다.

예:
- 3.05 → 삼쩜영오
- 0.5%p → 영쩜오-퍼센트포인트
- 2조 8천억 원 → 이조 팔천억 원
- 3번 확인했다 → 세-번 확인했다
- 3번 버스 → 삼번 버스

명확한 발화 대상 잔여 표면은 완성하되 주변 한국어 조사·어미는 바꾸지 않는다.
</RESIDUAL_READING_NORMALIZATION>

<DEFERRED_N_BEON_PATTERNS>

번호·ID 대상이면 Sino 수사와 `번`을 붙이고, 실제 행위 횟수이면 native 수사와 `번` 사이에 ASCII `-`를 쓴다.
조사 없이 `N번 + 동작 서술어`가 이어지면 횟수를 우선한다: `3번 처리했습니다 → 세-번 처리했습니다`.
`3번 항목을 처리했습니다`, `3번을 처리했습니다`처럼 번호 대상이 명시되면 번호 읽기를 선택한다.
해석이 둘 이상이면 원형을 유지하며 이미 확정된 읽기와 하이픈을 다시 판단하지 않는다.
</DEFERRED_N_BEON_PATTERNS>

<STANDARD_PRONUNCIATION_ENHANCEMENT>
4단계 전용 규칙 모듈이 단일 표준발음으로 확정한 표면은 입력에 이미 적용되어 locked되어 있다. 이를 원래 철자로 되돌리거나 다른 발음형으로 바꾸지 않는다.

아래 STAGE4_WORK_PLAN에는 현재 입력에서 실제로 허용된 문맥 후보의 위치, 원형, 출력 후보와 판단 지침이 JSON으로 제공된다. 각 후보는 원형 유지 또는 options 중 하나만 선택할 수 있다. 후보 목록에 없는 위치나 발음은 새로 만들지 않는다.

- 인기: 독립 어휘 `인기`는 규칙 모듈이 `인끼`로 확정 적용한다. `개인기`, `무인기`처럼 더 긴 단어 내부에는 적용하지 않는다.
- 대가: `대가를 치르다`나 `노동의 대가`처럼 비용·희생 의미가 확정된 문맥은 코드가 이미 `대까`로 적용한다. `예술계의 대가`처럼 거장 의미가 확정된 문맥은 후보에서 제외해 원형을 유지한다. 그 밖의 미해결 `대가`만 후보로 주어지며, 값·비용·보상이면 `대까`, 뛰어난 사람·거장이면 `대가`를 선택한다.

후보가 입력에 없거나 뜻이 불확실하면 새 발음형을 만들지 않는다. 일반 접미사 패턴이나 비슷한 단어로 확대하지 않는다.
</STANDARD_PRONUNCIATION_ENHANCEMENT>

<COMPOUND_SPEECH_BOUNDARY>
3단계와 동일하게 매우 긴 복합명사를 한 덩어리로 오독할 가능성이 높고 내부 의미 경계가 확실할 때만 ASCII 하이픈을 넣을 수 있다. 단어당 1개로 제한하지 않는다.
한글 글자와 순서는 유지한다. 조사·어미·서술어·접사·영숫자 모델 코드·보호 표면에는 넣지 않는다.
WORK_PLAN의 options는 등록된 명사·의미 단위의 모든 분석이 동의하는 경계 또는
검토된 전문용어의 상위/하위 결합 경계만 포함한다. 일반 명사 분석은 명사부
6~32음절, 구간 각각 3음절 이상이며 검토된 국가·지역 앞 수식어는 2음절도
허용한다. 검토된 전문용어의 정확한 경계는 더 짧은 구간도 가능하다.
분할안은 최대 6개다.
후보 존재는 적용 명령이 아니다. 문장 전체의 뜻과 수식 관계를 확인하고 양쪽이 자연스러운
의미 덩어리이며 실제 발화에 도움이 될 때만 분할안을 선택한다. 국가·지역 수식어와 핵심 명사구,
독립된 기관명과 하위 조직의 최상위 경계를 먼저 검토한다. 핵심 명사구는 잘게 끊지 않는다.
한 경계와 여러 경계 분할안을 비교해 단어 길이와 의미에 필요한 만큼만 끊는다.
후보 순서는 구간 길이와 과분할 억제 기준일 뿐
의미 우선순위가 아니다. 첫 후보를 자동 선택하지 않는다.
기관명·제품명·서비스명 같은 이름도 여러 명사의 결합이며 내부 의미 경계가
명확하면 분할안을 선택할 수 있다. 이름이라는 이유만으로 후보를 생략하지 않는다.
단일 고유명사 내부 음절, 미등록 어휘, 여러 해석이 가능한 단어, 이미 자연스러운 단어는
원형을 유지한다. 불확실하면 id를 생략한다. 명사마다 하이픈을 넣거나 기존 하이픈에 추가하지 않는다.
예: 개인정보처리방침 → 개인정보-처리방침, 인공지능기술개발 → 인공지능-기술개발,
신용카드사용내역 → 신용카드-사용내역. 개인정-보처리방침, 인공-지능기술개발은 금지한다.
여러 경계 예: 인공지능데이터분석시스템 → 인공지능-데이터분석-시스템.
서울대학교병원강남검진센터 → 서울대학교병원-강남-검진센터,
초중등교육법시행령개정안 → 초중등교육법-시행령-개정안,
탄소중립녹색성장기본계획 → 탄소중립-녹색성장-기본계획.
한국수출입은행은 유지하되 한국수출입은행무역금융본부는
한국-수출입은행-무역금융본부가 가능하다. 인공-지능-자율-주행은 금지한다.
소상공인자작경영지원자금사업의 `자작`을 삭제해서는 안 된다.
검토된 기관명 속 LH·GTX는 이미 확정된 한글 약어 읽기를 보존하고,
WORK_PLAN에 표시된 인접 경계만 선택한다. LH는 약어 앞뒤, GTX노선은
약어 앞을 먼저 검토하고 발화에 도움이 될 때만 뒤의 `-노선` 후보도 선택한다.
`지티엑스노선`을 한 덩어리로 유지해도 된다.
이름 예: 국가산업안전지도 → 국가-산업안전지도, 서울도시철도공사 → 서울-도시철도공사,
한국해양진흥공사 → 한국-해양진흥공사, 대한적십자사혈액관리본부 → 대한적십자사-혈액관리본부.
농림축산식품부, 한국전력공사, 노사정위원회는 그대로 둔다.

하나만 선택하고 두 변경을 임의로 결합하지 않는다.
상위 의미 경계가 하나로 확정되어 하이픈 option만 제시된 복합명사에서는

<FINAL_VALIDATION>

3. 같은 id를 두 번 선택하지 않았는가?
4. required=true인 후보를 모두 선택했는가?
5. 불확실한 선택 후보를 생략했는가?

<SELECTION_CONTRACT>
정확히 다음 JSON 형태만 출력한다.
{"schema_version":1,"decisions":[{"id":"S4-0001","option":0}]}

- 변경할 후보만 decisions에 넣는다. 선택하지 않은 후보는 코드가 원형을 유지한다.
- required=true인 후보는 반드시 정확히 한 번 넣는다.
- option은 해당 후보의 options 배열에서 선택할 0 기반 정수 인덱스다.
- options가 한 개이면 유효한 option은 0뿐이다. 후보를 기계적으로 전부 선택하지 않는다.
- id와 option 외의 필드를 decision에 넣지 않는다.
- 후보가 없거나 변경할 선택 후보가 없으면 {"schema_version":1,"decisions":[]}를 출력한다.
- 입력 문장 전체나 변환 문장, 설명, 코드 펜스를 출력하지 않는다.
